Privacy and data use

SignalTube is a personal local application using YouTube API Services. Use is subject to the YouTube Terms of Service and Google Privacy Policy.

Only an explicit refresh sends requests to Google: the selected public channel handles or playlist identifiers, your API key and ordinary network information including your IP address. No OAuth, account subscriptions, personal watch history or synthetic records are sent. There are no third-party analytics, ads, embedded players or remote image requests in this dashboard.

Public channel titles, channel/playlist/video identifiers, video titles and publication dates are cached locally. SignalTube also records local retrieval times and a quota ledger. These local diagnostics are not YouTube statistics. The manually requested Shortlist uses cached publication dates, explicit local preferences and optional imported creator event counts for transparent application scores. These are not YouTube metrics or quality predictions. No model, transcript fetch or remote inference is used. Building a shortlist makes no network request, remembers the chosen shortlist options locally and consumes no API quota. Watch next retains only selected matching fingerprints, build time and local options in the personal database. Titles, URLs and API metadata are not copied there. Opening the saved list never selects replacements; reasons are derived from current valid cache and local choices.

API metadata is removed from the active cache at expiry (30 days) when the app runs, before it can be displayed. Expired data is unavailable offline. A stopped computer cannot run deletion jobs; on next launch expiry cleanup precedes use. No background service has been installed. Live-cache backups are not created automatically.

The API key lives in an owner-only file under the app's data folder in secrets/youtube.key (normally ~/.local/share/signaltube for the desktop package, or the project's var directory for the source edition). It is not placed in HTML, URLs, exported data or application logs. Other programs running as your Linux user remain within the same trust boundary. Key storage is not disk encryption. You can revoke the key in Google Cloud without deleting your personal data.

Your favourites, pins, categories, saved status, review choices, persistent filters and single-step Undo are held in a separate owner-only personal.sqlite3 database. Video choices use a local fingerprint to match cached items; no YouTube titles, publication dates or URLs are copied into that personal database. When metadata expires, saved choices remain but details and playback links are unavailable until the item is cached again. These choices are not sent to Google.

Explicit Takeout imports are stored locally under the app’s data folder in takeout, in separate owner-only databases per profile. They contain historical watch timestamps, available video titles/IDs, creator names/IDs and imported subscription membership. Raw export files are read only when explicitly selected, never scanned for or copied by the importer. These user-provided records are independent of the API cache; the API-cache expiry process never deletes them. Preview runs in memory, and import requires a matching confirmation ID. Imports are additive and preserve original exports.

The synthetic demo, public API cache and private key are separate. Local review states belong to SignalTube, not your YouTube account. Opening a YouTube link sends you to YouTube under its own privacy rules; SignalTube does not claim that opening means watching.

To remove local data, stop the app and request removal of the dedicated live cache and/or key. This does not delete your YouTube account data. No deletion of personal files or key replacement occurs silently. There is no cloud account or external support recipient for this personal build.
